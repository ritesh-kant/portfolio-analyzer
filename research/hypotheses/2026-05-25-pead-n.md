# Hypothesis: PEAD v5 — ML Selection with Repaired Revenue & Net Profit Data

## 1. Hypothesis

A LightGBM classifier using the same 10 pre-registered features as Strategy M,
but trained on data where `revenue_cr` and `net_profit_cr` are patched from 132
Tickertape quarterly income statement CSVs (DEC 2023 → MAR 2026), can identify
Midcap 150 earnings events with post-announcement drift ≥ 100 bps net, achieving
per-trade Sharpe ≥ 0.5 on the dev period.

## 2. What Changed from Strategy M

Strategy M was killed (2026-05-25) for three root causes:

| Root cause                                                  | M status                                            | N fix                                                                                                                                        |
| ----------------------------------------------------------- | --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| RC1: P-threshold structurally unreachable                   | Calibration collapsed (max P=0.4677)                | Fixed by live earnings features restoring model discrimination                                                                               |
| RC2: `net_profit_cr` 100% null, `yoy_revenue_prev` 70% null | Dead features → model trained on 1 earnings feature | 132 CSVs bulk-downloaded; `net_profit_cr` 100% filled, `revenue_cr` 100% filled for new quarters                                             |
| RC3: No underlying PEAD signal (mean −54 bps)               | Confirmed by L (rules) and M (dead ML)              | Untested with live earnings-quality features — if no signal exists even with proper features, Strategy N closes the PEAD family definitively |

**Known limitation:** Tickertape data covers only 10 quarters (DEC 2023–MAR 2026).
The train period (2015-01-01 → 2023-06-30) still has:

- `net_profit_cr`: 0% fill
- `revenue_cr`: 4.3% fill (screener.in partial)
- `yoy_revenue_prev`: 0.2% fill

This means `net_profit_margin` and `yoy_rev_growth` features are NaN for ~100%
of training events. LightGBM handles NaN via learned missing-value branches, so
the model will route all events with null net_profit_margin to a single branch
during training. In dev, 32% of events have non-null net_profit_margin. This
is a distribution shift but one where the model can at minimum use other features
to discriminate — unlike M where the feature was globally dead in both splits.

**Why this is still worth testing:** M's Spearman ρ = 0.044 was measured with
the model effectively using 1 earnings feature (yoy_eps_growth). The theoretical
mechanism requires conditioning earnings quality ON market reaction — a signal
that requires yoy_rev_growth and net_profit_margin to distinguish quality beats
from low-quality beats. RC3 ("no signal") was established under conditions of
feature poverty; it deserves one confirmatory test with richer features.

## 3. Mechanism (same as M)

day is underappreciated and will drift up over the following 5 trading days.

## 6. Model Architecture (identical to M — immutable)

```
LightGBM binary classifier:
  objective         = binary
  max_depth         = 3
  n_estimators      = 100
  learning_rate     = 0.05
  min_child_samples = 20
  subsample         = 0.8

Training: purged k-fold (k=5, embargo=10 trading days) on 2015-01-01 → 2023-06-30.
Inference: score all dev events; trade events with P ≥ 0.50.
```

| Spearman ρ (P vs return)   | **0.081 (p=0.027)** | 0.044 (p=0.225) | ↑ significant |

**Root cause analysis:**

The data quality fix (Tickertape income statement download) improved the
Spearman ρ from 0.044 (not significant) to **0.081 (p=0.027, marginally
significant)**. This is the first signal that earnings quality features
carry some ranking information.

However, the calibration degeneracy is unchanged:

- Max P = 0.4677 < threshold 0.50 → zero trades
- Only 8 unique calibrated P values across 784 dev events
- Calibration plateau persists

**Why calibration is still broken:** The `net_profit_cr` column was 0% filled
in the TRAINING period (2015–2023). Tickertape's 10-quarter window covers only
DEC 2023 → MAR 2026, leaving training data-starved. The model trains with
`net_profit_margin` = NaN for ~100% of training events → isotonic calibration
learns a plateau at the training base rate (37%) → all dev P-scores cluster
just below 0.50.

**The partial fix worked:** ρ improved, confirming the theoretical mechanism.
But fixing dev data without fixing training data is insufficient — the model
needs historical earnings quality data (pre-2023) for calibration to produce
discriminative P-scores.

**Required to unlock:** Historical quarterly income statements (pre-2023) to

- Screener.in bulk export (historical quarterly P&L) — free tier limited
- NSE XBRL filings parser — free, requires engineering effort
- Paid data: Refinitiv, Bloomberg, Tofler

## 11. Decision

**KILLED — 2026-05-25.** Zero dev trades (P-threshold structurally unreachable
due to training-period data poverty). Spearman ρ improved to 0.081 (p=0.027),
indicating a weak signal exists, but calibration cannot produce P ≥ 0.50 without
historical net_profit data in the training window.

The PEAD signal family (L, M, N) is now definitively closed. Re-entry requires
historical quarterly P&L data for 2015–2023 and a new pre-registered hypothesis.
